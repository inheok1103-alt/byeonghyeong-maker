# 임용 종단(2007-2026) 출제로직 — 정답 폐쇄성 3중 게이트

## 핵심 원리
- 정답 폐쇄성 3중 게이트(모든 빌더 불변식): 어떤 문항도 (실재성=정답 요소가 지문/제시자원에 실제 출현) ∧ (유일성=제약 교집합이 정확히 1개만 통과) ∧ (자가검증성=코드가 학생답 없이 정답을 재산출)을 통과해야 출제하고, 하나라도 실패하면 폐기·재생성한다. 이것이 임용 20년(2007~2026)을 관통하는 단일 설계축이다.
- 규칙 내장성(self-contained rule closure): 근거 우주를 지문/규칙박스 안에 폐쇄한다. 'from the passage'·'Based on <A>'로 외부지식·상식·취향의 개입을 차단하고, 정답은 텍스트 내부 규범만으로 결정되게 한다. 유의어 뉘앙스 구별처럼 '정확한 독해가 아닌 사전지식'으로 갈리는 문항은 이의제기 위험으로 금지.
- 선지 부분집합 배타 + 전량설명(all and only): 규칙-사례 판정형은 5개 선지를 서로소/포함관계 부분집합(a / a,b / a,b,c / b,c / c)으로 구성해 직관·부분매칭·요행을 차단하고, 'account for all N examples' 전량설명 제약으로 부분정답을 폐쇄한다.
- 최소대립·부정증거 경계표시: 정문/비문(*), 적격/부적격(#) 쌍을 나란히 두어 변별 자질을 정확히 하나만 남긴다. 정문 단독은 규칙 과소결정 → 정답 근거에는 반드시 최소대립쌍(정답어↔근접오답어 포함)을 첨부해 유일성을 학습자가 스스로 재구성하게 한다.
- 범주고정(single-category underlining): 한 세트의 밑줄·표적을 동일 문법범주로 통일해야 '왜 틀렸는가'를 언어단서로 유일 서술할 수 있다. 무작위 5범주 혼합은 근거서술 자체를 불가능하게 하므로, 서술형 파생 세트에서는 범주혼합을 금지한다.
- 담화표지가 논리연산을 지정한다: 빈칸·순서·삽입은 인접 담화표지(However/Therefore/This paradox)·대용어(this/the editor)·정관사·정보흐름의 응집사슬이 정답의 논리관계와 인접쌍을 잠근다. 대표 오답은 '방향 역전'과 '범위 과대'로 고정해 표지의 방향판정만으로 풀리게 한다.
- 오답 매력도 = 실제 오개념 × 근접도 위계: distractor는 무작위가 아니라 학습자 빈출오류(affect/effect, rise/raise, 수일치 착시, 능동↔수동, 준동사↔동사)에서 우선 생성한다. 난도는 semantic(같은 의미장) > syntagmatic(문맥 공기) > orthographic(철자유사) > unrelated 근접도로 조절하되, 강한 매력 오답은 문항당 1개로 제한해 난도 폭주를 막는다.
- 선지 동질성 + 표면단서 제거: 선지는 품사·어절수·문법형태·난이도가 병렬이어야 한다(정답만 유독 길거나 유일한 to부정사/복수형이면 내용 몰라도 맞힌다). stem 단어반복(clang)·관사(a/an)·단복수 문법단서·정답표현 재노출을 제거하고, 정답 번호를 세트 전체에서 균등 분산하며 절대어·이중부정·all/none of the above를 회피한다.
- 서술형 폐쇄 = 슬롯 + 지정근거 + 축약상한: 자유해석을 (a)해석 슬롯 (b)지정 구간에서 근거 N개 (c)'연속 N단어 초과 인용 금지'의 3레버로 닫는다. 채점키에 필수 근거 문장ID·필수 키워드·감점 항목을 내장해 코드가 표절율·근거포함을 자동 채점하고, 축약금지가 '이해 없이 베끼기'를 원천 차단한다.
- 조건영작 등가류 폐쇄: 제시어 전수사용 ∧ 구조틀(목표구문/어형변화/금지어) ∧ 원문 의미일치의 교집합으로 정답 문장의 좁은 등가류를 정규식·구문패턴으로 정의한다. 정답검증기는 학생답 없이 '스펙 충족 문장집합이 공집합이 아니고 구조가 유일한지'를 자가검증한다.
- 정의밀도 유일화(definition-in-context): 빈칸 정답어 주변에 동의 재진술·예시·대조 단서를 2회 이상 심어, '단서만으로 정답을 역추론 복원 가능한지' 테스트를 통과한 문항만 출제한다. 추상 정의를 구체 재진술로 바꾸는 것으로 난도만 낮추고 폐쇄장치는 유지한다.
- 난도 계단식 교육과정 이식: 임용의 폐쇄장치는 보존하되 (자질을 교육과정 내 규칙으로 한정, 예/조각 수 축소, 위반지점을 콤마·어형 등 표면표지로 노출)해 난도만 낮춘다. 한 시험지 안에 쉬움-중간-어려움을 안배하고, 고1은 단서 표면화·탐색범위 축소, 고2는 SAME-word 이중슬롯·근거2개+반론차단으로 상향한다.

## 엔진 개선안
### [상] engine.js · grammarSites()
현재 site는 수일치/to부정사/관계사/조동사/동명사/태 6종뿐. 신규 site 추가: (a) 병렬구조(and/or 전후 형태 불일치), (b) 수일치 착시(핵 주어와 동사 사이에 of구·전치사구를 끼워 근접명사 수로 오형 유도), (c) 형용사↔부사(-ly), (d) 관계대명사 vs 관계부사(where/when↔which/that). 각 site에 category 필드를 부여하고, wrong 후보는 note(규칙명)가 명확하고 'bad로 바꿔도 의미가 통해버리지 않는(=규칙상 명백 오류)' 것만 통과시키는 필터를 건다.

### [상] engine.js · gen_grammar()
opts.fixCategory 파라미터 추가. 현재 seen[note] 분산 로직 대신, 켜지면 5개 밑줄을 동일 category site에서만 뽑고(임용식 범주고정) 정답 site 1개 외 4개는 같은 범주의 정문(正文) 정상용법으로 채운다. 이렇게 해야 '틀린 것 고르고 근거(위반 규칙명) 서술' 서술형 파생이 언어단서로 유일 채점된다. 단문 fallback 분기에도 note를 answer/explain에 명시.

### [상] engine.js · distractors()
tier 파라미터('easy'|'hard') 도입해 3층 오답 구조를 명시화: easy=FALLBACK/GLOBAL_POS 무관어+철자유사(orthographic), hard=ENRICH.syn(같은 의미장, paradigmatic)+doc.contentTokens 공기어(syntagmatic) 비중↑. 단 ENRICH.syn 중 lemma(정답)와 뜻이 동일한 후보는 정답자리 유일성을 깨므로 계속 제외(현 lemma 필터 유지). 반환 후보에 층 태그를 달아 해설·난도 배분에 사용.

### [상] engine.js · gen_blank()
correct 문장 선정 뒤 'definition-scaffold 게이트' 추가: 인접 문장에 정답 어구의 동의 재진술/예시/대조 단서가 2개 이상 실재하는지 역추론 테스트(단서만으로 정답 복원 가능?)를 통과해야 채택, 부족하면 재선택·폐기. distractor 4개는 syntagmatic(K.COLLOCATIONS 기반 지문 핵심어 공기구) 1개 + 명백 무관(K.ABSTRACT_PHRASES) 3개로 3층 고정. 빈칸 직전 토큰이 a/an이면 distractor 첫 글자 모음/자음을 정답과 일치시켜 관사단서 제거.

### [상] engine.js · gen_order() / gen_insertion() (getWindowCued)
현재는 cueScore만으로 창을 고름 → 응집사슬 실검증 추가: 각 조각 경계마다 '뒤 조각 첫머리 대용어(this/he/she/the+N)·정관사구의 선행사가 앞 조각에 실재'하는지 체크해 유일 순열을 보장하고, 실패하면 조각 경계를 재분할하거나 문항 폐기. 내신 하향용으로 조각 수 3 파라미터(gen_order size=3) 노출.

### [중] engine.js · makeQuestions()
조립 마지막에 정답 위치 균등화(key balancing) 후처리 추가: items 전체의 정답 index 분포를 집계해 특정 번호가 몰리면 선지 순서를 seed 무작위 재배치로 평탄화. 부정 발문('적절하지 않은/일치하지 않는') 문항에는 강조 플래그를 실어 report.html/exam.html이 굵게 렌더하도록 신호.

### [중] engine.js · gen_summary() (요약 one-word 빈칸 서브모드)
현행 (A)(B) 핵심어 방식에 'one-word from passage' 서브모드 신설: 토픽문장 추출→1문장 패러프레이즈 요약문 생성→슬롯의 POS·의미에 유일하게 맞는 지문 표제어를 정답키로. '본문에서 한 단어로, 어형변화 가능' 제약 자동부착. 검증: (정답어가 지문에 실재) ∧ (슬롯 유일) 통과 못하면 폐기. 고2 상향은 SAME-word 이중슬롯(dual-slot 검증기 재사용).

### [중] engine.js · gen_vocab() (이중빈칸 dual-slot 모드)
대조축 연결어(but/whereas/on the other hand)를 공유하는 두 문장에서 (A)(B) 두 토큰을 반의/혼동어로 교체하고 선지를 짝(pair)으로 제시하는 모드 추가. dual-slot 검증기: 후보가 슬롯A·B 양쪽에서 각각 유일 통과할 때만 채택하고, 한쪽만 유일하고 다른 쪽에 복수해가 생기면 리젝트해 '가짜 유일해'를 차단.

### [상] api_team.js · buildGrammar + types.json 어법 guide
guide에 명시: 5밑줄 통상 시행은 범주혼합 허용하되 서술형 파생 시 범주고정, wrong 선지는 '의미가 통해버리는 유사형태 배제·규칙상 명백 오류'만, 정답 site의 note(규칙명)를 해설에 필수 노출. 수일치는 핵 주어와 동사 사이에 of구·삽입절로 핵 주어를 은폐하라는 착시 지침을 유지·강화.

### [상] api_team.js · buildArrange (배열영작)
정답검증을 3중 게이트로 강화: (제시어 전수 사용) ∧ (연어/병렬 제약 통과) ∧ (LanguageTool 문법적격 + 원문 문장과 의미일치). 통과 못하면 문항 폐기·재생성. 난도 파라미터: 하향=구 단위 6~8상자로 미리 청킹+시제/연어 힌트 1개, 상향=청킹 해제(단, distractor 불필요어는 섞지 않음).

### [중] api_team.js · buildConditional (조건영작)
'frame + lexical-slot' 스펙 추가: 목표 구문(관계사/분사구문/가주어)·제시어·허용 어형변화·금지어·문장수를 스펙으로 받아 모범답안 등가류를 정규식·구문패턴으로 정의. 정답검증기가 학생답 없이 '스펙 충족 문장집합이 공집합 아님 ∧ 구조 유일'을 자가검증하고 실패 시 재생성.

### [상] api_team.js · buildEssay + 서술형 rubric 생성
rubric 3요소를 자동 생성: 해석 슬롯 / 증거 개수·지정 구간(section·문단 ID) / 축약한도('연속 N단어 초과 인용 금지'). 정답키에 필수 근거 문장ID와 금지 연속어 수를 넣어 코드측이 학생답안의 표절율·근거 포함 여부를 자동 채점. 채점기준 노출·코드 반영 전에는 승인 게이트('반영할까요?')를 통과.

### [중] api_team.js · buildFactCheck (factcheck0) → checklist-diff 모드
'체크리스트 대조' 모드 신설: 규칙 리스트<A>+실행 텍스트<B>를 입력받아 각 규칙항의 준수/위반 플래그를 코드가 판정→위반 항목·근거를 정답키로 자동생성. '왜 위반인지 한 줄' 서술형으로 파생. 규칙이 유한·열거형이라 이진 매칭으로 폐쇄되어 내신 서술형 자동채점 중 가장 분쟁이 적은 형태.

### [중] engine.js + api_team.js 공용 · contrast-pair injector 유틸
모든 빌더가 호출하는 공용 최소대립쌍 주입기 신설: 정답 근거를 (정문/비문, 정답어/한 자질만 다른 근접오답어) 쌍으로 해설과 검증 양쪽에 자동 첨부. 오답 선택지 생성 시 '한 자질만 다른 근접 오답'을 우선 채택해 변별도를 올린다.

### [중] types.json · 빈칸/어휘 guide
명시 규칙 주입: (1) 유의어 뉘앙스 구별 금지, 오답=반의어·혼동어·문맥상 명백 오답, (2) 정답 표현이 stem 다른 위치에 그대로 재노출된 구간 회피, (3) 빈칸 직전 관사·수 표지가 정답에만 자연스럽지 않도록 오답의 첫 글자·수를 정답과 정렬, (4) 해설에 '원문 X → 문맥상 반대/무관' 근거 병기로 이의제기 차단.

### [하] knowledge/exam_types_v1.json + engine.js GEN 레지스트리
신규 빌더(규칙박스+사례판정, 규칙도출 그리드, 분류표, 코멘터리 빈칸, 매칭+근거, 체크리스트 대조)를 유형DB에 impl=builder-needed로 등재하고 각 항에 fidelity 등급과 난도 계단(고1/고2) 메타를 추가해 makeQuestions의 타입 선택·안배가 참조하게 한다.

## 고등내신 신규 템플릿
- [규칙박스+사례판정] <A>에 고1 문법 1줄 규칙(예: '계속적 용법 관계사는 앞에 콤마가 있고 that을 못 쓴다', '수동태는 목적어를 주어로 올린다') + <B>에 학습항목 예문 5개(관계사·시제·수일치·가정법) → 발문 '규칙을 지키는 문장을 모두 고른 것'. 난도↓: 선지 부분집합 3~4개, 위반지점을 콤마·어형 표면표지로 노출. 난도↑: 위반 은폐 + 규칙명 1문장 서술. (음운·형태론 제외)
- [O/X 최소대립 경계 규칙도출] 목표문법(관계사 격·수일치·시제일치·준동사) 예문을 옳음/틀림 2열로 배치 + '두 열을 가르는 규칙 한 가지를 명명하고 1문장으로 서술'. 별표 비문 대신 O/X 예문쌍을 나란히 제시해 경계를 눈에 보이게. 난도↓: 자질 교육과정 내 한정·예 3~4개·'제시된 예를 모두 설명'으로 요행 차단. 난도↑(고2): 규칙명+예외 1개까지 요구.
- [요약 one-word 빈칸] 교과서·모의 지문 토픽문장을 짧은 요약문으로 바꿔 빈칸 1개, '본문에서 한 단어로 쓰시오(어형변화 가능)'. 정답=지문에 1회만 나오는 핵심 명사/형용사. 난도↓(고1): 동의어 치환 최소·정답어 위치를 앞 문단으로 좁혀 탐색부담↓. 난도↑(고2): 서로 다른 두 문맥에 SAME-word 이중슬롯.
- [담화표지 어구빈칸] 120~150단어 지문 + 빈칸 인접에 However/Therefore/For example를 또렷이 남기고 빈칸을 문장 전체가 아닌 핵심 어구로 축소. 선지 5개에 '방향이 반대인 오답'과 '범위가 과대한 오답'을 배치해 표지의 방향판정만으로 풀리게. 난도↑: 표지 약화·추론 범위 확대.
- [응집사슬 3조각 순서배열] 첫 문장 + 3조각(내신 표준), 대용어(this/he/the editor)·연결어 선명. 각 조각 첫머리 대용어의 선행사가 앞 조각에 실재하도록 설계해 유일 순열 보장. 난도↓: 대용어 명시. 난도↑: 대용어 약화하고 시간·논리 순서 단서만 남김.
- [체크리스트 대조] '좋은 요약 규칙 5가지 vs 학생 요약문'(또는 '좋은 글쓰기 원칙 vs 예시 글')을 대조해 '안 지킨 항목 2개와 근거'를 찾게 함. 규칙이 유한·열거형이라 이진 매칭으로 폐쇄되어 서술형 채점분쟁이 가장 적음. 난도↓: 규칙 4~5개·위반이 표면적으로 드러나게 설계.
- [코멘터리 빈칸 + 밑줄 함의 서술] 짧은 내러티브/수필 지문 + 해설 문장(코멘터리) 빈칸(정답=본문의 상징·비유어 한 단어) + 밑줄부 함의를 '본문 근거로 우리말 1문장'. '4연속어 초과 인용 금지'. 난도↓: 해설이 의미를 직접 재진술·1단어 우선. 난도↑: 감상 근거 2개 + 반론 차단.
- [조건 분류 + 근거 인용] 밑줄 친 수식어 3~4개 중 (비제한적인 것/특정 범주)만 전부·오직 고르고 이유를 한 문장으로 쓰되 반드시 본문 근거어를 인용. 기준은 1개(콤마 유무)로 단순화. 채점: 근거에 필수 포함 키워드 지정, 근거칸에 본문어가 없으면 부분점.
- [매칭 근거대응] <A>에 글의 기능·구조 라벨(주장/근거/예시/반론, 문제/해결, 원인/결과) + <B> 지문을 주고 문장을 라벨과 1:1 대응시키고 근거를 재진술. 태그가 유일하게 결정되는 문장만 출제(중의적 문장 배제). 오답형은 '흐름상 어색한 문장 고르기'로 파생.
- [어법 범주고정 5밑줄 + 근거서술] 한 지문에 동일 범주 밑줄 5개(전부 준동사, 또는 전부 관계사)를 배치하고 '어법상 틀린 것 1개와 그 근거(위반 규칙명)'를 서술. 범주 통일이 정답을 언어단서로 유일화. 난도↓: 오류를 명백한 규칙위반으로, 정문 밑줄은 같은 범주의 정상 용법으로.

## 신규 빌더
- gen_rulecase (규칙박스+사례판정): 규칙을 술어함수(predicate)로 코드화해 각 사례 a~e를 이진 평가하고 정답 집합을 자동 산출 → 복수정답·정답없음을 원천 차단. 선지는 서로 다른 부분집합으로 구성하고 '전량 만족(all and only)' 발문. essay의 '어법 고쳐/찾기' 서브타입과 결합해 '규칙을 어긴 문장 고르기'로도 파생. 입력: 규칙 술어 스펙 + 지문에서 추출한 학습항목 예문.
- gen_rulegrid (규칙도출 그리드): 지문·문장에서 목표문법 토큰을 추출해 정문/비문 2열 최소대립 그리드를 생성하고 정답=구별 자질 라벨+근거로 둔다. '제시된 예를 모두 설명(account for all N)' 제약을 자동 삽입하고, 선택된 자질이 두 열을 100% 분리(반례 0)하는지 코드가 검증한 뒤에만 출제. 고2 상향은 규칙명+예외 1개 요구.
- gen_classtable (분류표): 지문 어휘/동사를 자질표(가산성·타동성·동사상 state/activity/accomplishment/achievement·어원 접두사 의미)로 태깅하고, 표에서 '한 기준만으로 정답이 갈리는' 항목만 채택. '기준 1개 = 정답 1개' 불변식을 검증기에 강제해 두 기준이 동시에 필요한 모호 항목은 자동 배제. 예: '진행형이 반복을 뜻하는 동사 2개 고르기'.
- buildCommentaryBlank (코멘터리 빈칸): 지문에서 상징·비유 후보어를 추출해 그 의미를 풀어쓴 해설문(코멘터리)을 생성하고 원어를 빈칸화(본문 출현 강제). 짝으로 '밑줄 함의' 서술형을 파생하되 모범답안이 본문 문장으로 역검증되도록 근거 링크를 저장하고, '4연속어 초과 인용 금지'를 채점 루브릭에 내장. (본문 실등장 ∧ 해석 부합 ∧ 문법·연어 적합) 3조건 교집합으로 정답 1단어 수렴.
- buildMatchEvidence (매칭/근거): 문장별로 담화기능 태그(주장/근거/예시/반론, 원인/결과)를 달고 태그가 유일하게 결정되는 문장만 문항화(중의적 문장 배제). 오답형(불일치)은 태그 충돌 문장을 심어 생성하고, 채점 루브릭에 '근거문 지정 + 연속 인용 상한'을 자동 첨부. 임용의 '불일치 단계 2개 고르기'를 '흐름상 어색한 문장 고르기'로 이식.
- buildChecklistDiff (체크리스트 대조): 규칙 리스트 + 실행 텍스트를 입력받아 각 규칙항의 준수/위반 플래그를 코드가 판정하고 위반 항목·근거를 정답키로 자동 생성. 주관 개입이 최소라 내신 서술형 자동채점 중 가장 안전한 폐쇄형. buildFactCheck(factcheck0)의 서브모드로 구현.
- verifyClosure (공용 정답검증기): 모든 빌더가 출제 직전 호출하는 3중 게이트 유틸(실재성·유일성·자가검증성). 통과 못하면 폐기 신호를 반환해 makeQuestions의 재시도 루프(현 6회)가 재생성. dual-slot 검사, 전량설명 반례0 검사, 응집사슬 선행사 실재 검사, definition-scaffold 역추론 검사를 서브루틴으로 포함해 각 빌더가 필요한 것만 선택 호출.
- contrastPairInjector (공용 최소대립쌍 주입): 정답 근거를 (정문/비문, 정답어/한 자질만 다른 근접오답어) 쌍으로 만들어 해설과 검증 양쪽에 자동 첨부. distractors()·gen_grammar·gen_vocab이 오답 생성 시 '한 자질만 다른 근접 오답'을 우선 채택하도록 소스로 제공해 변별도와 유일성을 동시에 담보.
