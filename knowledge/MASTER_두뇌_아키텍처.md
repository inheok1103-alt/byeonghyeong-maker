# Ray English 출제 두뇌 — 마스터 아키텍처 (뇌 + 신경다발 + 파이프라인 + 하네스)

생성: 2026-07-09 · 목적: 연구·논문·종단분석을 기반으로 '문제 퀄이 기가 막히게' 나오도록, 모든 것을 **로직화 → 파이프라인 → 하네스 → 자기진화**로 총괄하는 단일 두뇌 아키텍처. 원칙: 문제를 '만드는' 것이 아니라 **신뢰도·타당도·변별도로 측정·보장**한다.

## 0. 다섯 층 (뇌가 총괄, 신경다발이 관통)
```
[연구층] 종단기출·원서·논문·외부검색
        │ (채굴·종합)
        ▼
[로직층] knowledge/*.md · types_v2 가이드(◆로직·◆기출·◆공리·◆난이도·◆심화·측정)
        │ (매 생성 프롬프트 주입 = TYPERULE)
        ▼
[생성층] api_team 파이프라인 — 코드빌더(정답 코드제어) + LLM빌더(신경다발) + 게이트
        │ (문항 산출)
        ▼
[측정층] 하네스 — 코드검증 → 신경다발 솔버(변별도·난이도·오답효율) → 타당도 게이트
        │ (합격 문항만 납품 / 불합격은 개선·폐기)
        ▼
[진화층] 뇌(server_brain 24h) + 신경다발(MoA) — 검증 결과·연구를 로직층에 환류(logic_evolve)
        └────────────────── 피드백 루프 ──────────────────┘
```

## 1. 신경다발(MoA) — 층을 관통하는 공통 기제
여러 무료 LLM이 **토론·투표·증류**로 단일 LLM 한계를 넘는다. 구현: `ensemble()`(메타-LLM 종합), `deliberate()`(교사군집 회의), `reviewOptions()`(선지 검수관), `addon_key_guard 솔버`(정답 다수결 교정). → 생성·측정·진화 전 층에서 재사용.
- 생성: 핵심 논지 추출을 앙상블로(USE_ENSEMBLE).
- 측정: 능력 계층 솔버(상/중/하)로 변별도·난이도 추정.
- 진화: 교사 회의로 로직 개선안 도출.

## 2. 연구층 (근거) — 이미 축적 + 지속
- 수능/학평 종단 2010-2025: `mock_exam_logic.md`(발문·오답·빈도·트렌드·유형별 ◆기출).
- 임용 종단 2002-2026: `exam_logic_longitudinal.md`(정답 폐쇄성·난도계단·내신 이식).
- 원서 원리: `linguistics_exam_points.md`(범주/기능·FMU·담화관계·연어).
- 측정학·영어교육학: [진행] 언어평가 유용성·타당도·문항분석·교육과정 → `measurement_logic.md`(예정).
- Ray's Drill: `rays_drill_*.md`(방법론·3공리·클러스터).
- 두뇌(server_brain)가 매시간 코퍼스 연구·기출 누적으로 연구층을 키운다.

## 3. 로직층 (로직화) — types_v2 가이드에 모든 연구를 주입
각 유형 guide = ◆로직(L/SM/SY/PI) + ◆방법론 + ◆심화게이트 + ◆출제범위(원서 28) + ◆기출(학년차) + ◆공리(어법 3공리) + ◆난이도(하/중/상) + ◆측정(예정). refine_guides_v1~v5로 idempotent 주입. TYPERULE로 매 생성 프롬프트에 삽입.

## 4. 생성층 (파이프라인) — 정답을 코드가 통제 + 게이트
- 코드빌더(어법·어휘·순서·삽입·무관·빈칸code·지칭·전체배열): 정답·밑줄·오류주입·선지 전부 코드 결정 → 정답 키·위치 정합은 코드 보장(내용 정확성은 solverGate·codeGate 등 게이트가 검증 — 100% 정확성 주장 아님).
- 게이트(코드): 밑줄 분산(spreadOK), 문법 범주 다양성, 어법 무오류주입 차단(문법검사 대조), 어휘 품사보존·중복차단, 비단어 차단(badInflect), 태그/CJK 위생, 정답 유일성(factcheck 통제생성).
- LLM빌더(요지·주제·서술형): 신경다발 파이프라인(논지→정답→오답→검수).

## 5. 측정층 (하네스) — 신뢰도·타당도·변별도로 퀄 보장 [핵심 신규]
실제 응시자 없이 **신경다발 솔버를 응시자 대리**로 문항 퀄을 계량:
- **추정 변별도 D** = 상능력 솔버 정답률 − 하능력 솔버 정답률. 게이트: D가 낮으면(상하위 모두 같게 반응) 변별력 없음 → 개선/폐기.
- **추정 난이도 P** = 중능력 솔버 정답률. 게이트: 너무 쉽/어렵 배제(목표 대역).
- **오답 효율** = 각 오답을 고른 솔버 비율. 게이트: 아무도 안 고른 죽은 오답 → 재설계.
- **정답 폐쇄성(구인타당도)** = 상능력 솔버 일치·근거 인용 가능. 복수정답(표 분산)=폐기.
- **내용타당도** = 유형-구인 적합(유형이 재려는 능력을 실제로 재는가), 성취기준/어휘수준 정렬.
현재: addon_key_guard(코드검증→솔버 다수결→위생)가 초기형. → 능력계층 솔버 + 오답효율 + D/P 지표로 확장(측정학 연구 반영).

## 6. 진화층 (뇌) — 환류
- `server_brain.js`(GitHub Actions 24h): 자가학습(selfLearnStep)·코퍼스 연구·교사 회의(deliberate) → learned_rules·research_log·hourly_report. 프록시 전체체인 연결로 한도 소진에도 지속.
- `logic_evolve.js`: 로직 결함 감사→토론 제안→스테이징→승격(버전업). 측정층의 실패 패턴을 로직층 개선으로 환류.
- `neural_bundle.js`·`evolve.js`: MoA 증류·홀드아웃 벤치마크 승격게이트(자체 LLM).

## 7. 총괄 오케스트레이션 (한 문항의 생애)
```
연구층(근거) → 로직층(TYPERULE) → 생성층(코드/LLM 빌더+게이트) → 측정층(솔버 D·P·오답효율·타당도)
   ↑                                                                          │
   └────────── 진화층(뇌: 실패패턴→로직개선, 성공샘플→자체LLM 증류) ──────────┘
```
목표: 각 문항이 **연구 근거 → 로직 준수 → 정답 폐쇄 → 측정 합격**을 모두 통과해야 납품. 통과 못 하면 개선하거나 버린다(많이 만들되 최종은 퀄로 자른다 — Ray 원칙).
