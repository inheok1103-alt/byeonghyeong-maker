# 교사 회의록 — 변형공학: 예시 교체 창작 시 사실성 검증(허위 정보 방지)

- 일시: 2026-08-23T19:40:19.666Z
- 구분: 자동연구
- 판정: **부분반영** (우선순위 상)
- 사유: 계층화된 DB 구축 및 목적 기반 필터링은 사실성 검증의 한계를 보완할 수 있으나, 시스템 구축 비용과 복잡성이 높아 즉각적인 전면 반영은 현실적이지 않다. 특히 '다중 소스 크로스체크'는 기술적 구현 난이도가 높고, '출처 계층화 점수'의 객관적 산정 기준 마련이 필요하다.
- 반영 방법: 1) **계층화된 DB 우선 구축**: 국가기록원·교육부(공식) + 국제학술 DB(예: Scopus, Web of Science) + 현장 사례 DB(예: 산업 표준 문서, 전문가 인터뷰)까지 3단계로 계층화하여 단계적 도입. 2) **목적 모듈(Mode Selection) 우선 개발**: '수능/내신 오류 방지용(공식 DB 전용)'과 '창의적 예시용(학술+실무 혼용)'으로 구분하여 우선 구현. 3) **LLM 프롬프트 개선**: 사용자 선택에 따라 DB 계층을 자동 선택하는 기능 추가. 4) **검수자 템플릿 개선**: DB 계층 선택 근거와 사실성 판단 기준을 명시하도록 필수 입력란 추가.

## 대화문
- **교사#28114 (교육과정·성취기준·EBS 연계형)**: 변형공학(예시·교재 교체·창작)의 **사실성 검증은 필수**다. **왜?** 수능/내신 출제 원칙에 따르면 *사실 오류는 채점 오염*을 일으켜 신뢰성을 떨어뜨리기 때문이다. 구현 방법은 **1)FactCheck DB(국가기록원·교육부 자료) 연동 API**, **2)LLM의 사전 fact-checking 프롬프트("출처: OOO, 날짜: OO") 강제 출력**, **3)검수자용 팩트체크 템플릿(출처·일자·맥락 포함)**을 시스템에 통합하는 거다.
- **교사#69350 (어휘·연어·서술형 채점 정밀형)**: **불충분한 fact-checking DB의 한계성 우려**

FactCheck DB 연동 API가 **국가기록원·교육부 자료에만 의존**한다면, **최신 연구 동향·국제 표준·실무 현장 사례** 등 *비공식 but 유의미한 사실*을 누락시킬 위험이 크다. 특히 **변형공학의 창의적 예시**는 *학술적 검증보다 현장 적용성*에 초점을 맞추는 경우가 많아, **표준 DB만으로는 사실성을 보장하기 어려운 구조**다.
- **교사#16052 (언어학 이론·실용·상황형)**: **시스템 개선 방안:**
1) **계층화된 사실성 검증 DB** 도입: *국가기록원·교육부(공식)·+ 국제학술 DB(최신 연구)·+ 현장 사례 DB(업계 표준·실무)*를 병렬 연결해 **DB 간 우선순위 점검 로직**(예: "최신 연구 > 공식 자료")을 설계한다.
2) **LLM의 fact-checking 프롬프트에 "DB 계층 선택" 옵션** 추가: 사용자가 *창작 목적*(예: "학술적 사실성" vs "현장 적용성")에 따라 **적합한 DB 소스를 자동 선택**하도록 유도.
3) **검수자 팩트체크 템플릿에 "DB 계층 선택 근거"** 필수 입력란을 추가, **사실성 판단의 투명성**과 **변형공학의 목적 맞춤형 검증**을 동시에 확보.
- **교사#60220 (화용·함의·패러프레이즈 정교형)**: **신규 제안:**
1) **다중 소스 크로스체크 로직**: 공식 DB(국가기록원·교육부) + 비공식 but 신뢰성 확보된 출처(예: *Peer-reviewed 논문·산업 표준 문서·전문가 인터뷰*)를 **동시 크롤링 후 상호 검증**하는 *이중fact-checking* 시스템을 도입한다. 이때 **소스 간 상충 시, "출처 계층화 점수"(예: 정부 > 학술 > 실무)**를 기반으로 우선순위를 자동 산정한다.
2) **목적 기반 사실성 필터링**: 변형공학의 *출제·학습·창의적 예시* 등 **목적 모듈(Mode Selection)**을 시스템에 내장해, 각 목적에 맞는 **사실성 검증 강도(예: "수능 오류 방지용=공식 DB만" vs "창의적 예시=학술+실무 DB 혼용")**를 자동 적용토록 한다.
