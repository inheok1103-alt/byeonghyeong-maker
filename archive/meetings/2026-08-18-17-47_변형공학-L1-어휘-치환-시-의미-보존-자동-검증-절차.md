# 교사 회의록 — 변형공학: L1 어휘 치환 시 의미 보존 자동 검증 절차

- 일시: 2026-08-18T17:47:00.815Z
- 구분: 자동연구
- 판정: **부분반영** (우선순위 상)
- 사유: 의미 보존 자동 검증 절차의 필요성과 실효성 간 균형은 인정되나, 화용론적 오류 및 사전/모델 편향 문제는 해결해야 할 핵심 과제로 남아있음. 또한 다중 계층 검증 체계와 민감도 분석의 도입은 의미 동등성 확보에 기여할 가능성이 높음.
- 반영 방법: 1) 교사#93828의 화용론적 보정 레이어(대화행위 분류 + 형식성 등급) 및 교사#40530의 대역어 검출 강화를 **필수 계층**으로 통합. 2) 교사#84698의 다중계층 의미 동등성 검증(의미망 + 임베딩 + 화용론적 규칙베이스)과 시맨틱 드리프트 감지 알고리즘을 **선택적 보완 계층**으로 추가. 3) 민감도 분석 자동화는 **우선순위 하**로 적용하되, 위험도 0.7 이상 시 **수동 검토 알림**을 발동하는 방식으로 구현.

## 대화문
- **교사#52592 (언어학 이론·EBS 연계형)**: 변형공학(L1→L2 어휘 치환)의 의미 보존 자동 검증은 **필요성과 실효성 간 균형 문제**로, **찬성** 입장이다.

**근거**:
1) **의미론적 동등성** 확보를 위한 **의미망(WordNet/ConceptNet) 기반 정합도 검증** 가능.
2) **구조적 일관성** 유지 via **의존구문분석(Dependency Parsing) + 의미역 분석(Semantic Role Labeling)**.

**구체적 구현**:
- **1단계**: 대치 후보어의 **시맨틱 필드(Semantic Field) 매칭** (e.g., "car"→"automobile" via WordNet synset).
- **2단계**: **의미역 일치성** 검증 (e.g., "drive a car" → "drive an automobile"에서 *Theme* 역할 유지).
- **3단계**: **문맥 임베딩** (BERT/RoBERTa 기반)으로 **의미적 거리(semantic similarity)** 계산 (threshold > 0.85).
- **교사#93828 (담화·응집성·패러프레이즈 정교형)**: **위험성**: 의미망/임베딩 기반 검증은 **사전/모델 편향(bias)**으로 인해 **미묘한 의미 차이(예: "car" vs. "automobile"의 문화적 뉘앙스)**를 포착하지 못할 수 있다. 특히 **비격식체(L1) → 격식체(L2) 치환**에서 발생하는 **화용론적 오류**는 자동 검증으로 해결하기 어렵다.
- **교사#40530 (듣기·구어체·실용·상황형)**: **보완 제안**:
1) **화용론적 보정 레이어 추가**: 대화 맥락(예: "운전해" vs. "차량을 운전하십시오")을 **대화행위 분류(Dialogue Act Tagging)**로 감지하고, 형식성 등급(register scale)을 부여해 **자동 검증 시 변수화** (e.g., formal_threshold = 0.92).
2) **대역어(cognate) 검출 강화**: L1-L2 간 유사어(예: "car" vs. 스페인어 "carro")는 **의미망 + 음운론적 일치도**를 동시에 평가해 오류 가능성 차단.
3) **사용자 피드백 루프 통합**: 검증 실패 시 **다중 어휘 후보 재추천** 시스템을 연동, 교사와 협업식 재검증 구조로 보완.
- **교사#84698 (어휘·연어·패러프레이즈 정교형)**: **추가 제안**:
1) **다중계층 의미 동등성 검증** 도입: **의미망(synset) + 임베딩(semantic similarity) + 화용론적 규칙베이스(예: 격식체 전환 패턴 DB)**를 **계층적 voting 시스템**으로 결합, 각 계층별 신뢰도 가중치(0.3/0.5/0.2)를 통해 **복합 오류 패턴**을 포착.
2) **시맨틱 드리프트(semantic drift) 감지 알고리즘**: L1→L2 치환 시 **원문 vs. 변형문 간 맥락 임베딩 차이**를 **시간적/공간적 변화(예: "car"→"vehicle"의 현대 vs. 고전문학 맥락)**까지 분석하는 **타임슬라이스 임베딩** 적용.
3) **민감도 분석(Sensitivity Analysis) 자동화**: 치환 어휘의 **의미 파괴 위험도(예: "big"→"large" vs. "huge")**를 **맥락 내 도메인별 민감도 점수**로 산출, 위험도가 0.7 이상 시 **수동 검토 알림** 발동.
