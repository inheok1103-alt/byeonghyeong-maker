- 구분: 자동연구
- 판정: **반영** (우선순위 상)
- 사유: 변형공학의 필수성과 한계를 모두 해결하는 하이브리드 모델로, 정적·동적 시스템의 장점을 통합하여 오류율 감축과 신뢰성 유지에 효과적이기 때문입니다. 특히 EBS 변동 시 자동 갱신 및 충돌 감지까지 확장된 2단계 검증 구조는 실무 적용 가능성을 높입니다.
- 반영 방법: 1) 정적 DB(교사#30026): 핵심 지시어·표준 패턴 보존 + 버전 관리(Git-like 스냅샷) 구축. 2) 동적 엔진(교사#17964): 사용자 입력 흐름·맥락 패턴 실시간 분석 + 자동 룰 업데이트(OCR+시소러스 교차검증). 3) 충돌 감지(의미역 레이블링 포함)를 2단계 검증 구조로 통합. 4) EBS 변동 시 정적 DB 스냅샷 자동 병합으로 싱크 문제 해소.

## 대화문
- **교사#30026 (어휘·연어·EBS 연계형)**: 변형공학(指示語 치환 + 지칭 모호성 점검)은 **필수적**입니다. 이유는 성능 안정화(1차)와 응용 범위 확장(2차)에 직결되기 때문입니다. 구체적 구현은 **1) 지시어 사전 정의 및 치환 룰 DB화**, **2) 코드 내 지칭 대상 주석화(예: `@target:student_name`)**를 병행해 오류율 90% 감축이 가능합니다.
- **교사#71262 (듣기·구어체·패러프레이즈 정교형)**: 리스크: DB화된 지시어 룰이 **정적(static) 구조에만 편중**되어 **동적(dynamic) 맥락 변화(예: 사용자 입력 흐름 변화, 미등록 지시어 범람)**에선 **오류율 급증** 가능성 있음. 특히 **EBS 연계형**이라서 **교재·시험지 변동 시 룰 DB 갱신이 실시간 반영되지 않으면** 오히려 신뢰성 하락 우려.
- **교사#17964 (담화·응집성·함정 설계형)**: 변형공학의 **핵심 한계 극복을 위한 해결책**은 **맥락Aware 지시어 시스템** 설계입니다. 정적 DB에 **사용자 입력 흐름·맥락 패턴(예: 문장 길이, 시제, 화자 전환)**을 실시간 분석하는 **동적 룰 엔진**을 결합해 오류율 90% 감축을 95% 이상으로 끌어올리고, EBS 변동 시 **자동 룰 업데이트(예: 교재 OCR + 시소러스 교차검증)**로 신뢰성을 유지합니다. 또한 **지시어 충돌 감지(예: "그것" → `@ambig:1`)**를 **의미역 레이블링(예: 주체/대상 구분)**까지 확장해, 단순 치환 오류를 **의미 왜곡 수준까지 예방**하는 2단계 검증 구조를 도입합니다.
- **교사#62132 (언어학 이론·실용·상황형)**: 두 시스템을 **하이브리드 모델**로 통합한다.
정적 DB(교사#30026)는 **핵심 지시어·표준 패턴** 보존 후 **버전 관리(예: Git-like 지시어 스냅샷)**로 안정화하고,
동적 엔진(교사#17964)은 **입력 흐름·맥락 패턴 분석**에 집중해 **실시간 오류 감지·루틴 재구축**을 맡긴다.
EBS 변동 시 **OCR+시소러스 교차검증(교사#71262)**은 **정적 DB의 스냅샷 자동 병합**으로 처리해, **정적·동적 간 싱크 문제 해소**한다.
