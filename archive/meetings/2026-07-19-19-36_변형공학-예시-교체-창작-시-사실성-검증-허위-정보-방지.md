# 교사 회의록 — 변형공학: 예시 교체 창작 시 사실성 검증(허위 정보 방지)

- 일시: 2026-07-19T19:36:51.943Z
- 구분: 자동연구
- 판정: **부분반영** (우선순위 상)
- 사유: DB 버전 관리와 실시간 필터링은 필수적이지만, '맥락 AI' 모듈의 구현 가능성과 비용 효율성을 고려할 때 우선순위가 낮습니다. 교사 3인 검토+DB 연동 시스템이 핵심 해결책으로 인정됩니다.
- 반영 방법: 1) DB 연동 시스템 구축: EBS/수능 교재 텍스트를 실시간 DB로 관리하며, AI 생성 예시가 DB에 미등재 시 자동 거부. 2) 교사 3인 이상 검토 시스템: AI 생성 예시가 DB에 등록되지 않거나 교재와 미묘한 차이가 있을 경우, 3인이 협의해 수정·등재. 3) DB 버전 관리: EBS 개정 시 즉시 최신 DB로 전환(예: 개정일 자정 반영).

## 대화문
- **교사#28114 (교육과정·성취기준·EBS 연계형)**: 변형공학의 필요성은 인정하지만, **사실성 검증은 AI의 영역이 아니라 철저히 인적·체계적 감독으로 해야 한다.**

**근거:**
1) AI는 허위 정보 생성(예: "2023년 EBS 교재에 존재하지 않는 문항")을 완벽히 차단하지 못한다.
2) 수능/내신 출제원칙(예: 문항 난이도 균형, 오류 없는 선택지)은 AI가 자체적으로 판단할 수 없다.

**구체적 구현 방법:**
- **교사 3인 이상**이 AI 생성 예시를 검토·수정(예: "2024년 EBS 수특 영어 12강 'assume' 예문 → 실제 교재 9페이지 문장")
- **DB 연동 시스템**으로 EBS/수능 교재 텍스트와 비교·차단(예: "AI가 만든 'assume' 예문" → 교재 DB에 미등재 시 자동 거부).
- **교사#69350 (어휘·연어·서술형 채점 정밀형)**: 체계적 감독이 사실성 검증을 보장할 것이라는 낙관은 **DB 연동 시스템의 사각지대를 무시**합니다. 예를 들어, EBS가 개정되거나 신규 교재가 발행되면 DB 갱신 시차가 발생해,在此期间 AI는 사실과 동떨어진 예시를 생성할 수 있습니다. 이 경우 교사 3인 검토도 '사후 대응'에 머물 수밖에 없습니다.
- **교사#16052 (언어학 이론·실용·상황형)**: **절충안:**
**1) 실시간 DB '버전 관리' 시스템**을 도입해 EBS/수능 교재 개정 시 즉시 최신 DB로 전환(예: "2024년 3월 개정 → 3월 1일 자정 자동 반영").
**2) AI 생성 전 '사전 필터링+교사 협의' 병행:** AI가 예시 생성 시 **DB에 미등재된 키워드/문장**을 자동 차단하되, 차단된 항목은 즉시 **2인 1조 교사 팀**이 검토해 DB 갱신 여부를 결정.
→ 사각지대 최소화 + 사후 대응의 효율성 제고.
- **교사#60220 (화용·함의·패러프레이즈 정교형)**: DB 버전 관리와 실시간 필터링은 필수지만, **교재 DB의 '의미적 유사성'까지 검증하는 '맥락 AI' 모듈**을 추가해야 합니다. 예를 들어 EBS에서 'assume'이 '추정하다'로 쓰였다면, AI 생성 예시도 같은 맥락(추론·가정)만 허용하고, 실제 발췌문이 아니더라도 의미적 정합성을 DB로 검증해야 허위 변형(예: 'assume=떠맡다' 오용)을 차단할 수 있습니다. 이 시스템은 개정 시뿐 아니라 **교사 검토 후에도 DB에 '맥락 태그'로 축적**되어 사전 예방력을 높입니다.
