## 대화문
- **교사#88353 (평가·측정·EBS 연계형)**: **찬성** – 유령 오류는 지문 미제시가 원인인데, 이를 자동 차단하려면 **① "지문 부재" 시점(시험지·EBS 연계·기출 수록 여부)을 실시간 DB 매칭** 하고, **② 매칭 실패 시 즉시 오류 차단**하는 구조가 필요하다. (예: 수능 연계 EBS 자료와 시험지 문항 ID를 키값으로 검증하는 API 연동)
- **교사#33589 (통사·어법·서술형 채점 정밀형)**: **우려: 실시간 DB 매칭의 허점**
① DB가 최신 자료만 반영한다면, **구 EBS나 사설 교재(기출 변형 포함)까지 전수 검색하지 못해 허위 "지령 오류" 차단이 일어날 수 있다**. ② API 연동 시 **서버 부하(수능/모의고사 동시 접속)**로 인한 응답 지연이 오히려 오류 판정을 늦출 위험이 있다.
- **교사#76291 (영미문학·실용·상황형)**: **지문 부재 여부 검증의 다층 필터링 체계**가 필요하다.
1) **DB의 버전 관리 시스템**(년도·판본·수정 버전 구분)을 구축해 **최신·구버전·사교재까지 계층별 매칭**을 강제하고,
2) **AI 기반 추론 엔진**을 추가해 **"유사한 지문"(유사도 0.85+)**이나 **"표절 의심 항목"(출처 미기재 교재)**도 자동 flagging 처리한다.
이렇게 하면 실시간 부하 분산(CDN 캐시+레플리카 DB)과 오류 예방의 균형이 잡힌다.
- **교사#24459 (독해·논리·패러프레이즈 정교형)**: **신규 제안: "지문 부재" 검증의 '블록체인 인덱싱' 도입**
1) **분산 원장(Distributed Ledger)** 방식으로 각 지문·문항 ID를 블록체인에 기록해 변조·누락을 방지하고, **모든 평가지(수능/모의/사설 교재) 간 크로스체크**를 상시 가능하게 한다.
2) **LOD(Linked Open Data) 기반 API**로 외부 DB(국가교육DB, ERIC, JSTOR)와 연동해 **비공식 지문(번역·표절·2차 창작 포함)까지 포괄적 검증**을 실시간으로 수행한다.
→ *이 방식은 서버 부하를 샤딩(Sharding)으로 분산시킬 수 있으며, DB 최신화 주기 문제도 해소한다.*
